# Plan: NavStrip reactivity/Day P&L fixes + Derivatives Exp P&L/Snapshot/Payoff price-basis unification

## Context

Following the underlying-LTP desync fix (commits b1b946a8/5f2f9e42), the operator reported further symptoms: NavStrip values not updating reactively and briefly zeroing on return to the app, suspected wrong Day P&L, suspected wrong Exp P&L, and doubts about Snapshot/Payoff coupling and Payoff curve LTP accuracy. Two parallel read-only audits (NavStrip/Day P&L; Snapshot/Payoff/Exp P&L) confirmed the LTP fix itself is correct and not the cause — but found a substantial set of real, mostly pre-existing defects underneath, all traced to file:line with concrete repro scenarios. Working through the findings also surfaced an architectural simplification the operator approved: positions/holdings LTP should come from the book poll only (broker refresh, 5s foreground/30s background), not from live SSE ticks — SSE ticks stay reserved for roots/underlyings, which have no other frequent source. This removes a whole class of "one surface tracks ticks, a sibling only tracks the poll, they silently disagree" bugs by construction, rather than patching each occurrence individually.

## 1. Foundational: remove tick-based LTP for positions/holdings (operator-approved)

Positions/holdings LTP and Day P&L become purely poll-driven (5s/30s book poll cadence); roots/underlyings remain SSE-tick-driven (unchanged — needed for the Payoff curve, Snapshot LTP, etc.).

- **Frontend**: remove the live-tick delta term from `frontend/src/lib/data/nav.js`'s `livePositionDayPnl` — it collapses to `baseDayPnlForPosition(dcvRow)` with no `(liveLtp − pollLtp) × qty` adjustment. Remove `portfolioStore.svelte.js`'s equivalent live-price adjustment for positions (`_ltp = snap?.ltp ?? last_price` term flagged in the audit) — position/holding LTP should read `last_price` from the poll only, not `symbolStore`/`liveSnap`.
- **Backend**: remove `_override_stale_ltp_from_ticker`'s effect on **position rows** (`backend/api/routes/positions.py`) — this was patching `pnl`/`unrealised` from the ticker between polls; with positions now poll-only, this patch point goes away for position rows. (Confirm during implementation whether this function is also used for anything root/underlying-related that must stay — keep that part if so, remove only the position-row patching.)
- This directly removes the class of bugs: "Legs Day P&L doesn't track ticks while overlay DAY does" (now both are poll-only, consistent by construction), "Snapshot Exp P&L lags Legs TOTAL" (see §3, still needs its own fix since Exp P&L's remaining inconsistency is about *which spot basis*, not tick-vs-poll), and removes the live-price-adjustment freshness/session-guard gap entirely (no code path left to have that bug).

## 2. NavStrip reactivity and zero-flash

- **Zero-flash on return** (`frontend/src/lib/PositionStrip.svelte`): `_prevExecMode` defaults to `'idle'` but `executionMode` is already `'live'` on first real read, so a fresh component mount (leaving/returning to the `(algo)` layout area — not ordinary in-app navigation, which doesn't remount it) always registers as a "mode change" and force-resets `dispPositionsToday`/`dispHoldingsToday` to 0 until the next poll. Fix: initialize `_prevExecMode` correctly on mount (read the actual current mode instead of a hardcoded `'idle'` default), so a normal remount isn't misread as a market-open transition.
- **`portfolioAggregates` staleness** (`frontend/src/lib/data/portfolioStore.svelte.js`): P:2 lifetime, Margin, Cash, and Holdings value/lifetime slots only recompute on a price-tick-driven counter, missing store updates from fills/polls. Fix: add `bookPollerTick` (from `marketDataStores.svelte.js`, already used elsewhere e.g. `PositionStrip.svelte`/`RefreshButton.svelte`) and `bookChanged` (from `bookChanged.js`, already increments immediately on a fill) as additional tracked dependencies on the relevant `$derived`, alongside the existing tick counter. Given §1 removes tick-dependency for positions/holdings LTP specifically, this derived's *primary* trigger going forward should really be `bookPollerTick`/`bookChanged` (poll/fill-driven), with the price-tick counter retained only for whatever still needs live-tick sensitivity (roots).
- **P:1/H:1 blocked pending all-three-stores** (`portfolioStore.svelte.js:_portfolio`, "returns `_last` until positions, holdings, AND funds are all non-null"): add a partial-fallback — display P:1/H:1 as soon as positions/holdings are available even if funds hasn't landed yet, rather than blocking the whole aggregate on the slowest of three independent fetches.

## 3. Day P&L correctness

- **Partial-exit baseline gap** (flagged as needing empirical verification, not yet confirmed as a live bug): `prev_settlement_pnl` (yesterday's `total_pnl`) may include yesterday's *realized* P&L unremoved for an overnight position that had a partial exit yesterday, per the audit's worked example (a −6,000 error on zero price movement). Before implementing a fix, do the empirical check the audit specifies: compare a real overnight position's `realised` field against its stored `total_pnl` from the prior session to confirm whether Kite's `realised` is day-scoped. If confirmed, the baseline (`backend/api/routes/positions_helpers.py`, `_resolve_prev_settlement_pnl`/equivalent) needs to subtract the realized component that's specific to yesterday's activity, not carry it forward wholesale into today's baseline.
- **Ticker-correction fallback collapsing Day P&L to tick-delta alone**: subsumed by §1 — once position rows are no longer ticker-patched, this fallback path (and its failure mode for zero-split rows) is removed entirely, not just fixed.

## 4. Derivatives: unify Exp P&L / futures valuation to one consistent price basis

Per the earlier operator decision (Payoff curve/marker use the anchor contract; everything else uses front-month), the remaining bug is that "everything else" doesn't consistently use front-month — it's split three ways.

- **`frontend/src/lib/data/portfolioStore.svelte.js`**: the Exp P&L calc currently prefers the polled `p.underlying_ltp` over the live front-month `_rootSpotCache`. Reverse the priority — always use the tick-driven front-month root spot (via `getUnderlyingSpot`/`resolveUnderlyingTradingsymbol`, already the SSOT from the earlier fix) as primary, falling back to the polled field only when no live root data exists yet. This makes Snapshot Exp P&L/Extrinsic and Legs TOTAL Exp P&L converge on the same source.
- **Futures valuation**: futures are currently valued at the root's front-month price via `_rootSpotCache`, even when the held future is a *different* (far) month than front-month. A future's Exp P&L must use its own contract's live price (`liveSnap(<the future's own tradingsymbol>)`), not the root's front-month resolution — these coincide only when the held future *is* the front-month contract. Fix in both `portfolioStore.svelte.js` and `+page.svelte`'s `expiryPnl(c, liveSpot)` call site for future-kind legs.
- **Anchor contract has no refresh path**: `strategy.spot_anchor_contract` isn't included in `_underlyingQuoteKeys`, so it's never subscribed via `loadUnderlyingQuotes`/batchQuote, and `payoffSpot`/`payoffPrevClose`'s Tier-1 live-tick read can silently serve a days-old localStorage-cached price. Fix: include the current strategy's anchor contract in `_underlyingQuoteKeys` (or an equivalent subscription path) whenever a strategy is loaded, so it gets both batch-quote refreshes and live ticks like any other tracked contract.
- **`strategy.spot` never refreshes while legs are unchanged**: `computeLegsKey`/`buildCleanLegs` (`frontend/src/lib/derivatives/pageLoad.js`) sends `ltp: null` for live legs, so the legs-signature cache key doesn't change when prices move, and `loadStrategy` skips every 5s poll refetch as a result — leaving `strategy.spot` (and everything computed from it: `chartTheoreticalAtSpot`, `_mergedEv`, `_mergedPop`, `chainSpot`) stale from whenever legs last changed, while `candidatesActualPnl` keeps moving live — an implicit double-count of price movement. Fix: `loadStrategy` needs to actually refresh on a timer independent of the legs-signature memo (the memo should prevent redundant re-fetches for *identical* requests, not suppress ALL periodic refreshes) — reinstate a periodic refetch (e.g. every 5s, matching the book-poll cadence) that isn't gated by the legs-key check.

## 5. Snapshot filter/value consistency and misc derivatives bugs

- **Snapshot row values ignore active filters**: rows are filtered by account/strategy (`_byUnderlyingTotals`), but their Day/P&L/Exp values (`positionsDerivedStore.getByRoot`) and the TOTAL row are computed across ALL accounts/strategies regardless of the filter. Fix: thread the same account/strategy filter into the value computation, so filtered views show internally-consistent numbers and TOTAL sums only the visible rows.
- **"EV" column mislabeled**: renders `_expVal` (Exp P&L) under an "EV" header whose tooltip promises expected value. Fix: either compute and show the actual per-underlying EV (if backend support exists) or relabel the column/tooltip to accurately describe what it shows.
- **Legs search box bleeds into computed totals**: `_legsExpPnlTotal`/`_expiryPnlOffset` iterate the filtered `displayedCandidates` (affected by the search box), while the curve itself is built from unfiltered `legs` — so typing in the search box shifts the curve/EV numbers even though it's meant to be a display-only filter. Fix: compute totals from the unfiltered leg set; use the filtered set only for which rows are *displayed* in the grid.
- **Payoff card can permanently stick in "loading"** on a switch to a position-less root: `_positionsRefreshedAt` is only set by `loadPositions`, not by the book-poller propagation effect, so `_strategyStale` can stay true indefinitely if the switch happens >30s after the last `loadPositions`. Fix: have the book-poller propagation path also update `_positionsRefreshedAt` (or have `_strategyStale`'s gate use a source that's reliably updated by both paths).
- **`_NEXT` virtual roots resolve to the wrong contract**: `resolveUnderlying` strips `_NEXT` and returns front-month, but `_NEXT` is documented elsewhere (`rootOf.js`, `ChartWorkspace.svelte`) as meaning "the back/next month." Fix `resolveUnderlyingTradingsymbol` to respect the `_NEXT` suffix consistently with its meaning elsewhere, rather than silently collapsing it to front-month.
- **`_underlyingQuotes` entries never pruned**: stale entries for a previously-selected, now-deselected root linger indefinitely and can be served by `_activeQuoteLtp`/`_clientPayoffStub`. Fix: prune entries for roots no longer in `_underlyingQuoteKeys` on each rebuild, or bound the map to only currently-tracked roots.
- **`spotAnchor.expiryISO` wrong**: set from `strategy.expiry` (the options' expiry) instead of the anchor future's own expiry, giving a wrong "rolls in N days" chip. Fix: source this from the anchor contract's actual expiry, not the strategy's option expiry.
